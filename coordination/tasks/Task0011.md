### Audit (starting target dc6e22c91b6b4b18e0f5625f57f7dae1f18f39a6)
- OFF, WHITE, AUTOMATIC and MANUAL share mode selection for UI and G-code; mode persistence and checksum unchanged. The temporary white toggle is not persisted. Profile edits retain their P=1..3 / S=0..255 validation, EEPROM addresses and response strings.
- AUTOMATIC chooses hotend heating/printing, then bed heating (overrides) or bed printing (only if idle), then cooldown only if idle. With two hotends the last qualifying hotend wins; preserve inherited ordering, defer policy decision. Idle becomes six-color cycling on the first whole elapsed second strictly greater than the 30 s delay (31 s), not at 30 s.
- Timer4 X43 PH3/PH4/PH5 (6/7/8) uses COM4A1/B1/C1 and OCR4A/B/C = level*80, one level/channel per 10 ms (255 ticks maximum), disconnects zero channels. RF1000 has no RGB definition; RF2000 and RF2000v2 share X43. X44 (32 / PC5 / FET2) is separate, including the single-hotend cooler retrofit; X19/X42/X45 are also outside Timer4 RGB. No HAL, connector, retrofit, PWM register or ISR schedule changes.
- Two bounded fixes: IDLE itself is the validity marker for its uint32_t start time, so exact zero (boot or rollover) cannot prevent color cycling. Explicit 32-bit elapsed subtraction is valid across AVR millis rollover. Active profile edits persist but cannot override temporary white until it is toggled off. Public API unchanged.
- Existing EEPROM code restores mode only, not the fifteen profile bytes written by the setters; no change to the persistence contract in this task. Check desired persistence policy separately. Invalid stored mode handling remains inherited.
