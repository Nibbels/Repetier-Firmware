### Separate link, planning and motion limits

For a uniform stream of nonzero linear G0/G1 segments of mean chord length L mm, density rho=1/L moves/mm and path speed v mm/s, requested segment rate lambda=rho*v. Over a nonuniform window use count/sum of path lengths and actual planned/executed times; do not average reciprocals. Classify E-only/retract, travel, zero-step rounded moves, comments, duplicate/resend, non-motion commands separately. Keep byte reception, complete frame reception, accepted commands, planned moves, queue publication, and executed segments as distinct counters.

Nominal UART 115200 8N1 yields 11520 incoming bytes/s, hence at mean B bytes per line the ideal input ceiling is 11520/B lines/s. Actual configured divisor/U2X, frame sizes, ACK window, resend and host latency need modeling. TX is full duplex but consumes IRQ/CPU; ACK/flow-control can still limit sender. At 40 B/line ideal ceiling is 288 lines/s; at 20 B/line 576. Example 100 mm/s, 40 B/line:

| Chord L mm | Moves/mm | Required moves/s | UART-only ceiling mm/s |
| --- | ---: | ---: | ---: |
| 0.05 | 20 | 2000 | 14.4 |
| 0.10 | 10 | 1000 | 28.8 |
| 0.20 | 5 | 500 | 57.6 |
| 0.50 | 2 | 200 | 144 |
| 1.00 | 1 | 100 | 288 |
| 10.00 | 0.1 | 10 | 2880 |

Mathematical ceilings only; not measured speed or axis limit. If link is saturated, packing does not increase incoming bandwidth. If planning is CPU-limited, packing may free CPU. If per-step cost alone exceeds budget, larger groups cannot fix it. Diagnose each bottleneck separately.

Model total demand as U_total = U_Timer1(n,axes,rate) + U_Advance + U_UART + lambda_G*C_parse_plan(queue,geometry,frame)/F_CPU + U_periodic + margin. Distinguish segment setup/completion, actual per-axis pulse density, lookahead depth, nested ISR cost, foreground exclusive cycles versus blocked/elapsed time. Avoid double counting.
