## Source audit

At `3ca412e7953eddcd6b8d2a4f29dec7e4878eddb7`, `UIMenuEntry::showEntry()` (ui.cpp 28–41) evaluates a positive filter as any matching bit and a negative filter as no matching bit. Unfiltered macros (uimenu.h 49–58) instantiate filter=0 and nofilter=0. DisplayModes.h defines PAUSED=4, FAN_RUNNING=8, PRINTING=16, FAN_MODE_PDM=128. Printer.h 199–201 combines the mode bits with printJob.isBusy(); PrintJob.h regards Printing, FilamentService and Draining as busy. Entering a submenu stores the pointer and positions; parent filters do not continuously constrain its lifetime.

**Counterexample:** Main -> Extruder -> Load Filament / Unload Filament. In uimenu.h 444–454 each of the two child entries and its parent entry use filter=0, nofilter=PRINTING|PAUSED. Both children are visible at idle, neither is visible on a subsequent busy/pause transition. The parent is hidden too but is not consulted by refreshPage. No always-visible Back entry exists in those lists; the physical back key is independent. The original adjustMenuPos backward scan reaches index zero then performs an unbounded forward scan at indices 0, 1, 2...; index 2 is beyond the actual PROGMEM array. navigateMenuItems alone stops on wrap, but nextPreviousAction subsequently calls adjustMenuPos. okAction can read and dispatch a hidden entry before a refresh; in particular UiActions.cpp 355–390 contains the filament-service commands without a menu visibility guard at dispatch. No physical outcome claimed.

This patch does not impose a new policy for an unfiltered child dialog reached through a subsequently hidden ancestor (e.g. Stop/PID confirmation). That is a separate command-admission question for the relevant owner, particularly Task0021.

## Draft policy and verification

- Preserve previous-visible then next-visible selection policy. Bound searches by numEntries, pop entirely hidden submenu(s), correct parent selection and scroll, clear stale edit/confirmation and horizontal shift. OK or next/previous arriving before selection correction consumes that key rather than acting on the replacement; after rendering, ordinary keys operate on the new visible selection. Keep visible children accessible even if an ancestor is hidden. No physical or persistent state changes.
- Replay extends the actual extracted showEntry, adjustMenuPos, navigateMenuItems, nextPreviousAction, refreshPage, pushMenu, menuEsc and okAction. Full real menu table, both widths, four modeled variants, all 16 combinations of the actual mode bits; all previous preheat, offset and navigation assertions retained. Unrelated dynamic fields stubbed only for visibility checks, dispatch spies record action IDs rather than operating hardware. Test idle->printing/paused, load and unload, refresh/OK/NEXT/PREVIOUS before refresh, main selection changes and active PWM frequency edit hidden by PDM. AddressSanitizer/UBSan and 10s replay timeout remain enabled.
