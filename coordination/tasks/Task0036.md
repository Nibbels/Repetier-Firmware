## Work and exclusive scope on activation

1. Inventory all reachable interrupt-disabled regions and source-level owners/callers, including interrupt guards/RAII, ATOMIC_BLOCK, CLI/SEI, saved/restored SREG, TIMSK0–5 and other interrupt enable/mask writes, implicit ISR entry and exits, compiler-generated sequences, inline assembly, core/library code and calculated-address register writes. Cover foreground, startup, all ISR paths, nested guards, early returns, errors and all board configurations; distinguish global IRQ disable from individual interrupt masks. Map each reachable site to linked instructions and function/call context; justify unreachable sites rather than silently dropping them.
2. Remove unnecessary or redundant masks by proving exclusive access, interrupt-independent ownership or a safe transaction admission/phase. Use byte-atomic state where suitable; volatile alone is not atomic for multi-byte state or read-modify-write on AVR. Preserve coherent snapshots, publication ordering, 16-bit timer register access, GPIO shared-bit ownership, ISR self-exclusion and prior SREG state; never blindly enable interrupts on exit.
3. Move expensive arithmetic, formatting, copying, preparation and potentially blocking work out of masked regions. No waits for UART/EEPROM/I2C/SPI or other peripheral progress, delay loops, periodic callbacks, dynamic allocation or unbounded loops under a global mask or within an ISR; distinguish a proven bounded atomic register handshake or required STEP/DIR timing from a blocking operation. Demonstrate any exception is indispensable, finite, and fits the real response budgets. Inspect transitive calls and masked callers, including inherited I=0; do not rely on a callee restoring interrupts if a caller already masked them. Keep thermal progress and cancellation available during longer foreground operations.
4. For each retained region document module, source location, variant, linked address/range, caller and execution phase, protected state/register, competing accessors, necessary invariant, entry/exit semantics, worst feasible duration in CPU cycles and microseconds, including nested masks and all reachable callees, proof/method, assumptions, and why no shorter safe implementation is justified. Record site-specific before/after counts and duration deltas; compute maximum *continuous* blackout, not just individual lexical guard length. For selective interrupt masks establish the affected vector and maximum service exclusion.
5. Compose global worst-case response bounds with real interrupt priorities, entry/exit costs, minimum arrival intervals, pending/coalesced flags, mask state, nesting, competing workloads and back-to-back paths. Include heater lease/compare and watchdog, Timer1 motion, Advance/PWM/timebase, UART RX/UDRE at fixed 250000 baud 8N1, and other active interrupt sources. Evaluate deadline and service-gap margin against actual requirements, not average time or a guessed common threshold. Distinguish software response from independent hardware/reset protections. Do not certify a finite bound with an unresolved reachable unbounded wait or unknown store/call path; resolve or explicitly block acceptance.
6. Build reproducible regressions and fault/interleaving tests for each changed ownership or mask, including inherited-mask restoration, simultaneous shared-port writes, TX backpressure, heater expiry, stop and motion reference, and all affected modules. Add or extend existing automated audit tooling so new/unclassified mask sites, changed proof fingerprints, unbounded waits and deadline regressions are detected on future linked builds. Fail closed on missing evidence rather than treating an incomplete graph as proof.
7. Work in small sequential commits, comparing each meaningful change to the same-variant baseline. Scope on activation is the maintained firmware, linked core/library code and necessary task-private tools, tests and docs for interrupt ownership/latency; avoid unrelated rewrites or hardware/config changes. Preserve single central Drive, fixed 24 queue slots, physical microsteps, protocol/resend, heater fail-off, calibration/EEPROM, Z/DMS/ECMP and all documented UI workflows.
