### Architecture and Task0009 contract

- Internal settings occupy the first 2048 bytes, signature 44 at address 0, protocol version 8 at 105 and additive modulo-256 checksum at 104 (skips its own cell). Extruder blocks start at 200 and 300, stride 100. Unused legacy cells are reserved, not free for reuse. The external matrix EEPROM is Task0006's scope.
- M205 is a selective report, not a full byte dump; preserve order, type IDs (0 byte / 1 int16 / 2 int32 / 3 float), precision, labels and 4 ms per-line pacing. M206 accepts raw address/type writes and reloads settings after recomputing the checksum, including incomplete commands. No protocol changes in this task.
- UI should edit through the owning service's validated setter, persist the documented typed slot(s) and update the checksum. Prefer existing `EEPROM::storeManualZOffset()` and `EEPROM::storePreheatProfiles()` for their dedicated settings. Do not persist the live SenseOffset as manual clearance, overwrite the stored threshold on a bulk save, enable the 230 V outlet at boot or move preheat storage out of its current tagged slots. Bulk `readDataFromEEPROM()` has hardware/derived-state side effects; it is not a pure getter or generic UI validation API.
- Defaults, validation and repair are deliberately asymmetric: some invalid values are rewritten, some only rejected or clamped in RAM, some preserve preexisting service values. Avoid a universal descriptor table without separate evidence for each policy and AVR resource cost. Current changes share only the M205 framing; read/write/default/migration code and address defines remain identical to starting target. No new state, no runtime descriptor storage, no changes to PreheatProfiles.cpp or the external EEPROM.
