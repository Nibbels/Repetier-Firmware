### Electrical sensitivity (calculation, not measurement)

Series R plus receiving pin/trace parasitic capacitance C forms a low-pass RC. For R=3300 ohm, ideal 10–90% rise time ~2.2RC: 10 pF -> 73 ns; 20 pF -> 145 ns; 50 pF -> 363 ns; 100 pF -> 726 ns. At 500k bit duration 2 us; moderate capacitance and short trace suggest plausible margin, not a guarantee. Evaluate threshold-crossing time for actual VOH/VOL, VIH/VIL, driver output impedance, leakage/pullups, supply/temperature/tolerance, sample phase, crosstalk/ground noise, power sequencing and probe capacitance. No assumption of total C from schematic. Do not remove/bypass resistors or alter USB circuitry. ## UART timing and priority

AVR vector priority is fixed by vector address, not runtime programmable; WDT, Timer1 COMPA, Timer0 COMPA/COMPB/OVF precede USART0 RX, which precedes UDRE. IRQ dispatch only when I=1 and source enabled, no automatic higher-priority preemption; SEI allows any enabled pending source (with instruction deferral), not only higher priority. References: datasheet interrupt table; https://onlinedocs.microchip.com/oxy/GUID-173AD72D-41FE-4760-A93C-7078A02BD908-en-US-7.1.1/GUID-AC530860-E255-4C0F-A772-5C0990312B01.html . HAL.cpp TIMER1_COMPA masks OCIE1A before its nested-service windows, reenables at exit; audit exact linked windows, not blanket sei or vector/timer remap. Avoid nested self-entry and interrupt storms. Timer0 PWM, Advance STEP/DIR, watchdog and atomic shared-state obligations take precedence over throughput.

Task0032 prior isolated linked report: Task0030 final archive 15050792432, SHA256 1ffbe5f295d08ff4c8306900080dbcda873fd839f1f9663cdd589cdadf05d151; successful RX 73 cycles, UDR read completed at cycle 31, nonempty UDRE 74 cycles, all four builds, incl entry/vector/return. Reproduce/verify tools/task0032/uart-isr-cycles.py in #101 (prior reported counts, not fresh measurement in this registration). At 500k nominal 320 CPU cycles per 8N1 frame; RX alone 22.81% if continuously saturated, TX alone 23.13%, combined ~45.94% excluding empty ISR, parser and other work. At identical byte volume per second, faster link does not intrinsically consume more cycles but makes bursts more concentrated. Task0030 isolated max masked RF2000v2 594 cycles ~37.1 us; NOT full-system WCET. Two-level receive FIFO plus shift register: overrun when both FIFO entries full, another completed character waiting and next start bit detected; no universal 40/60-us safe blackout because occupancy and phase matter. Compute conservative release-to-UDR-read response bounds including all masked regions, prior pending RX, higher-priority IRQs, entry/exit and instruction deferrals; sweep continuous/burst worst alignments and nested stack peaks. Aim for prompt drain within one frame (20us) from RX-ready where feasible, prove no overflow with actual occupancy/deadlines; not a guessed single ISR limit. Compare old build vs new same workload to test owner's timing hypothesis, without claiming historical causation.

2. Compare one-byte ISR to strictly bounded drain of already-ready FIFO (e.g. at most two bytes, no waiting), independent status-before-data per byte. Measure cost, latency, other IRQ delays and non-reentry.

## Loss-aware transport and additional code audit

Current receiveInterrupt reads UDR0 then silently discards byte when ring full. It does not read FE0/DOR0/UPE0. Microchip error flags are associated with FIFO data: UCSR0A must be read BEFORE UDR0 (https://onlinedocs.microchip.com/oxy/GUID-EC8D3BAB-0B5E-454F-AB6E-6A7C91C6F103-en-US-3/GUID-7B4385C0-7B06-44CC-B8BC-07E8CDDB8721.html). FE means bad stop bit; DOR means at least one character lost, not a count of lost bytes; UPE relevant if parity enabled, baseline 8N1. Distinguish hardware error flags vs software ring-full loss. A larger SRAM ring cannot prevent hardware DOR. Usable RX 127, TX 63 bytes; at 500k 127 bytes takes 2.54ms from empty with no consumer, only 63 TX bytes 1.26ms. No wired flow control, verify host actual byte credit, ACK/resend, binary/ASCII frame length, timeout, and already-in-flight USB/UART bytes; don't confuse ring capacity with command count. Repetier two parsed slots, motion queue 24.

Design a cheap sticky loss indication or saturating counters (separate categories) with atomic foreground consumption; preserve association/order with stream, prevent a corrupted partial command or subsequent tail from being accepted/executed. Explicitly handle previously queued valid commands, boundary ambiguity (ASCII newline vs binary arbitrary payload), numbered/resend and unnumbered frames, reset/reconnect, multiple loss events/races, checksum collisions and false emergency parse. Determine safe existing recovery/abort behavior with tests; do not blindly flush valid queued commands, acknowledge a corrupted command or treat loss counter as recovery. Report diagnostics in foreground only, rate-limited/read-only and compatible with host; no serial print/EEPROM writes from ISR. No new protocol fields until compatibility checked.

Audit rest of UsbSerial/GCodeInput/HAL: RX/TX head/tail ordering and wrap, atomicity/volatile, UCSR0B read-modify-write races between foreground/ISR, RX/TX IRQ enable state and stale flags, begin/reinit and register defaults, flush waits for ring empty not physical TX complete (check semantics/callers), write/flush spinning with IRQ disabled or nested context, blocking ACK and periodic service starvation, UDRE empty IRQ cost, optional direct TX fast path, ASCII/binary parsing/line numbers/resends, parser admission/credit and partial timeout, malformed input, emergency M112 latency and valid-command ordering. Check no concurrent producers or reentrant logging. Measure each issue before patch; no speculative optimization. Preserve unrelated behavior and existing tests.
