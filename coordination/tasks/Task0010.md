#### Sensor-to-output findings

1. `TemperatureSensors.cpp:217-317`: supported sensor IDs and calibrated temperatures preserved; false only means unsupported ID (301 C sentinel). Type 0 returns 25 C without reading ADC. ADC rails can convert to plausible low temperatures (e.g. ID 13 raw 4092 -> 0 C); ID 14 raw 4092 below -10 C. HAL ADC snapshot is atomic but has no timestamp/valid-generation bit, starts at zero, and can repeat last data. No raw validity/freshness authorization.
2. `TemperatureControl.cpp:25-200`: unsupported immediately requests zero; supported out-of-range readings increment a single static counter shared across controllers, but can enter regulation before count >10. Low values can request pidMax, high values are limited by measured cutoff. More than ten accumulated failures latch global/per-controller defect, print stop, all targets zero and dry mode; error-free passes decrement the counter, so time depends on controller order/count and history. No-rise check after configured 12 s with <1 C rise, and hold deviation >20 C; same counter. A successful hold check updates the next deadline to approximately one second (check exact arithmetic before changing). Prior error in same service suppresses subsequent decouple tests. Target off/decrease requests zero, target below room cutoff forces zero and clears integral/decouple. No independent detection of a stuck output or all off-state temperature rise. Fault reporting and print-stop serial messages precede the final all-controller zero requests; UsbSerial::write can wait on a full TX ring (UsbSerial.cpp:84-92), so do not use the latch instant as a proven upper bound on output-off latency. Move authorization removal ahead of reporting in the production safety design.
3. `HAL.cpp:579-580,640-703`: setHeaterDuty only writes requestedDuty. Timer0 COMPB latches masked duty once per 128-tick frame; duty zero is not a direct pin clear. Full duty has no in-frame falling edge; zero request takes effect at next frame (nominal <=32.768 ms **only while ISR runs**, not a measured bound). Watchdog ISR is separate and does not revoke duty; external watchdog reset path must be measured.
4. `TemperatureControl.cpp:242-437`: autotune tests only conversion supported status at entry, sets pidMax, skips normal defect/range/decouple/PID for selected controller in manageTemperatures, ignores later conversion return, writes duty directly. Excess-temperature guard (target+40), timeout (sum of elapsed half-cycle clocks >20 min), and successful finish clear autotuneIndex but do not explicitly clear duty before returning. Next periodic regulation may overwrite it; no guarantee of immediate off. Entry lacks global defect/dry-run guard, loop lacks explicit global fault abort. `GCodeThermal.cpp:214-231` allows bed controller; unconditional `extruder[controllerId].tempControl.stopDecouple()` at line 302 can index past extruder array for bed. Source finding, not executed on hardware or in host replay. Do not mix correction with PID tuning.

#### Watchdog and waits

- `Commands.cpp:43-82` takes PWM scan tick (~39 compare ticks = 9.984 ms) and calls HAL::tellWatchdogOk **before** temperature service; temperature tick ~391 compare ticks (100.096 ms). Tick flags coalesce; heartbeat does not prove valid sensor data or completed thermal service. `HAL.cpp:53-55,369-418`: WDT interrupt (~16 ms) toggles external WDI if heartbeat <20 s; interrupt-only mode, no direct heater shutdown. Physical supervisor routing/latency per heater safety doc not verified.

Generic controller wait has no general timeout or in-loop defect/dry-run break; rising wait can remain active after target zero on fault if measured temperature never reaches zero. Resume wait can return when pause no longer reheating. Keeping watchdog alive is not equivalent to making progress.

- Normal regulation: supported status and existing inclusive converted-temperature interval [-10,300] define validity (non-finite values also rejected); zero duty before reporting, counting or PID. Disabled sensor ID 0 is a non-measuring sentinel and cannot authorize heat. Invalid samples do not update PID history or integral. Shared debounce, global latch, decoupling thresholds, and recovery from a transient unlatched invalid reading remain; once any fault is latched all targets/duty requests go to zero before reporting or print stop. No-rise/hold checks still use the original accumulated-error threshold. Existing raw-rail ambiguity (e.g. ID 13 raw 4092 maps to 0 C) remains a documented gap, not a claim of raw input validity.
- Autotune: reject unavailable/latched/disabled/invalid input, invalid controller association, dry run, target outside room-temperature to heater-cutoff interval (bed also respects HEATED_BED_MAX_TEMP = 180 C), and excessive initial measured temperature. Reentrant request rejected without taking ownership of the active tune. Clear previous target when admitting/rejecting a non-reentrant request. Selected controller's periodic service immediately zeros an invalid sample or temperature above min(target+40, heaterCutoffC), retaining an abort marker even if its next direct conversion is valid. Explicit target-off cancels an active tune, including a zero-to-zero request through the bed setter; normal target remains zero throughout the tune. Direct reads are checked too; global/per-controller defect, dry run, cutoff/overshoot and timeout abort before further relay output. Bed uses this controller rather than indexing extruder[]; cooler indexing remains limited to hotends. Successful completion does not request another high phase; every admitted success/failure clears target and duty and releases ownership before notification/EEPROM storage. Optional explicit PID store remains supported and uses the same formulas. Subsequent normal service cannot restart the prior setpoint.

Covers per-channel invalid low/high/unsupported/disabled, recovery, bed isolation, confirmed fault before print stop, no-rise and hold drift, PWM frame, periodic heartbeat, wait, autotune entry rejection, late and transient invalid samples, transient overshoot, other controller fault, cutoff, timeout, target-off and reentry handling, successful cycles and explicit store including bed.
