#### Sensor-to-output findings

1. `TemperatureSensors.cpp:217-317`: supported sensor IDs and calibrated temperatures preserved; false only means unsupported ID (301 C sentinel). Type 0 returns 25 C without reading ADC. ADC rails can convert to plausible low temperatures (e.g. ID 13 raw 4092 -> 0 C); ID 14 raw 4092 below -10 C. HAL ADC snapshot is atomic but has no timestamp/valid-generation bit, starts at zero, and can repeat last data. No raw validity/freshness authorization.
2. `TemperatureControl.cpp:25-200`: unsupported immediately requests zero; supported out-of-range readings increment a single static counter shared across controllers, but can enter regulation before count >10. Low values can request pidMax, high values are limited by measured cutoff. More than ten accumulated failures latch global/per-controller defect, print stop, all targets zero and dry mode; error-free passes decrement the counter, so time depends on controller order/count and history. No-rise check after configured 12 s with <1 C rise, and hold deviation >20 C; same counter. A successful hold check updates the next deadline to approximately one second (check exact arithmetic before changing). Prior error in same service suppresses subsequent decouple tests. Target off/decrease requests zero, target below room cutoff forces zero and clears integral/decouple. No independent detection of a stuck output or all off-state temperature rise.
3. `HAL.cpp:579-580,640-703`: setHeaterDuty only writes requestedDuty. Timer0 COMPB latches masked duty once per 128-tick frame; duty zero is not a direct pin clear. Full duty has no in-frame falling edge; zero request takes effect at next frame (nominal <=32.768 ms **only while ISR runs**, not a measured bound). Watchdog ISR is separate and does not revoke duty; external watchdog reset path must be measured.
4. `TemperatureControl.cpp:242-437`: autotune tests only conversion supported status at entry, sets pidMax, skips normal defect/range/decouple/PID for selected controller in manageTemperatures, ignores later conversion return, writes duty directly. Excess-temperature guard (target+40), timeout (sum of elapsed half-cycle clocks >20 min), and successful finish clear autotuneIndex but do not explicitly clear duty before returning. Next periodic regulation may overwrite it; no guarantee of immediate off. Entry lacks global defect/dry-run guard, loop lacks explicit global fault abort. `GCodeThermal.cpp:214-231` allows bed controller; unconditional `extruder[controllerId].tempControl.stopDecouple()` at line 302 can index past extruder array for bed. Source finding, not executed on hardware or in host replay. Do not mix correction with PID tuning.

#### Watchdog and waits

- `Commands.cpp:43-82` takes PWM scan tick (~39 compare ticks = 9.984 ms) and calls HAL::tellWatchdogOk **before** temperature service; temperature tick ~391 compare ticks (100.096 ms). Tick flags coalesce; heartbeat does not prove valid sensor data or completed thermal service. `HAL.cpp:53-55,369-418`: WDT interrupt (~16 ms) toggles external WDI if heartbeat <20 s; interrupt-only mode, no direct heater shutdown. Physical supervisor routing/latency per heater safety doc not verified.
- `TemperatureControl.cpp:220-240,309-312` heater wait/autotune pump periodic actions. `GCodeThermal.cpp:59-190`: M109 hotend (5 min timeout + fault break), M116 all targets (no general timeout), M190 bed (fault break, no general timeout), all pump WaitHeater. Generic controller wait has no general timeout or in-loop defect/dry-run break; rising wait can remain active after target zero on fault if measured temperature never reaches zero. Resume wait can return when pause no longer reheating. Keeping watchdog alive is not equivalent to making progress.

Scan motion yields after 16 pulses; deadline-based scan and TWI services are foreground. Exception: `Printer.cpp:655-674` disableCMPnow(wait) loops with 1 ms delay, explicitly avoids periodic recursion, no heartbeat/thermal servicing in loop; assess callers and bounded duration before changing in appropriate task. No blanket wait-safety or worst-case latency claim.
