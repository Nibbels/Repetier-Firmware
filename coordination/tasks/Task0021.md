## Scope of first fixes

- Reject pidMax below 40 before applying relay output because the fixed [20,pidMax-20] clamp is otherwise inverted. Abort if the configured power limit changes during tuning. Do not change normal controller power limits.
- Refresh derived I-state limits and reset accumulated I-state when saving autotune gains, before writing EEPROM.
- Keep historical half-scale Ku unchanged; document it explicitly. Standard relay approximation uses 4*d/(pi*a), where a=(Tmax-Tmin)/2. Existing firmware uses full peak-to-peak, so correcting this without migration doubles all three gains for equivalent data. Preserve compatibility pending device traces.
- Extend actual-source replay: P/I/D arithmetic, saturation and target-off, J0–J4 and fallback J5 on hotend and bed, coefficient relations, I-state refresh, limits 0/10/39/40/41/255, power-limit change during tune, existing safety and cancellation cases. ## Further findings / next gates

- Relay amplitude is updated before evaluating the preceding cycle; use actual applied high/low duty for that cycle in any future corrected estimator. Extrema and period stability, amplitude floor, finite positive coefficients, cycle count and gain validation need explicit checks. Keep old J IDs as compatibility modes unless owner approves transition.
- PID assumes 100 ms and 1.5 s derivative span even when service delayed or samples skipped. Test actual service jitter and derivative history warm-up. Clamp before converting to AVR 16-bit int and validate externally supplied gains; do not change sample-time scaling without matched tests.
- I max is a real duty ceiling (hotend v1=130, v2/v3=120, bed=80). At equilibrium above this holding duty, zero steady error is not possible without feedforward or a larger integral allowance. Negative I is intentionally supported, with actual minimum PWM contribution -pidDriveMin/10. Panel drive changes write EEPROM but do not immediately recalculate derived limits; inspect all settings/restore/load paths separately.
- Autotune bypasses selected controller normal decoupling; existing timeout and cutoff are not equivalent to a validated no-rise/hold monitor. Raw rail ambiguity and hardware shutdown remain open per heater-safety.md. Check initial above-target heating, phase timeout, sensor noise, cooling fan/filament disturbance and independent overtemperature on dummy load before powered tests.
- Existing rules: J0 classic (0.6,0.5,0.125); J1 Pessen (0.7,0.4,0.15); J2 some overshoot (0.33,0.5,1/3); J3 no overshoot (0.2,0.5,1/3); J4 Tyreus-Luyben (1/2.2,2.2,1/6.3), expressed as Kp/Ku, Ti/Tu, Td/Tu. Pessen is aggressive and useful for fast hotends; Tyreus-Luyben is a robust starting point for slow beds. These are heuristics, not guarantees.
- Investigate SIMC/IMC and AMIGO using bounded step response identification; model/filament/fan feedforward is a later improvement. Sources: https://skoge.folk.ntnu.no/publications/2012/skogestad-improved-simc-pid/ ; https://doi.org/10.1016/j.jprocont.2004.01.002 (verify exact paper bibliographic details before formal citation); https://marlinfw.org/docs/features/model_predictive_control.html .
