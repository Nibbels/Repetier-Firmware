## Implementation and compatibility contract

Baseline: M111 bit 8 selected dry run and zeroed hotend targets, but left an already heating bed active; the panel's action 1077 zeroed both. The thermal-fault service reused the same bit, so a subsequent debug mask could temporarily remove the E admission predicate. The panel action was remotely reachable even without a current menu item. Removed debugDryrun(), enableDebugDryrun(), setSomeTempsensorDefect(bool), action 1077, the %dd formatter and obsolete dry-mode message. The historic changelog is not rewritten. The firmware source scan of all compiled sketch headers and translation units found no remaining old dry-run names or formatter, only the intentional bit-8 exclusion in the debug mask API and legacy admission logic. Other debug bits retain their numeric values (including unrecognized bits).

- Thermal faults and rejected legacy simulation requests are independent, sticky flag0 bits, combined by heatingInhibited(). Both latch the existing ExtrusionOutput inhibit mask's SafetyLock reason, discard pending Advance steps and lead under interrupt protection, and set all heater targets and requested duties to zero before stop/report. No new global SRAM allocation. A debug-mask change, motor enable, pressure recovery or print-stop cleanup cannot release SafetyLock. Boot clears runtime state; a real sensor fault can recur on the next sample.
- Positive target writes are suppressed at the controller boundary and the normal extruder/bed setters. Thermal service skips PID output while inhibited; invalid samples still zero affected duty immediately as before. Controller waits terminate, M109/M190 retain their thermal-fault abort checks, M116 terminates, autotune admission and cancellation honor the latch. The existing diagnostic M3200 P5 now invokes the same fault latch and print stop. Existing range/pressure/length and emergency protections are not weakened.
- Normal G-code E admission rejects E under either latch. For a thermal fault, an otherwise admitted mixed XYZ/E command may retain its XYZ component; queued/direct E pulses, Advance updates and M223 test steps remain blocked by the existing common output owner. There is no alternate simulation execution mode.
- On a valid received M111 with bit 8 (including mixed masks), reject at receiver admission before the ordinary stop-drain gate, and also at dispatch for internal scripts. The first request latches outputs off and stops the print. Report `Error:M111 bit 8 unsupported; job rejected. Stop host and restart printer.` unconditionally; the normal transport acknowledgment is not permission to execute a job. While rejected, discard subsequent machine-work commands at dispatch, including motion, heating, homing, extrusion, tools, feedrate and internal flash scripts. Pure M105/M111/M114/M115 remain available once stop-drain completes; M110 line synchronization and M112 emergency reset keep their original receiver-level behavior. During stop-drain, commands may be acknowledged and discarded. Physical panel navigation remains possible, but the shared heater/E inhibition still applies. Previously executed work cannot be undone. Legacy bit 8 is never stored as a debug flag.
- Recovery: stop the host stream and discard buffered host commands before intentionally restarting the printer. M111 S0, M110 or another ordinary debug mask cannot release the latch. M112 is an existing emergency reset, not a way to resume the rejected job. The latch is runtime-only, not persisted across reset; a host continuing to send after hardware reset must not be treated as part of this protected session. No live reset/relay/pulse timing validation has been performed.

## Task0016: deferred human-observed G-code sequence

**Do not run as a complete file.** Perform each segment only after software acceptance and explicit owner approval, one command at a time, with a console capturing serial output. Use the correct board variant, verified machine limits, unobstructed travel, working sensors and an available physical power cut-off. For the fault/rejection tests, isolate real heater power while de-energized and use instrumented outputs/test loads and valid sensors; disengage filament feed or monitor E STEP pulses without loaded filament. No live unplugging of sensors, intentional overheating or unattended operation. Stop immediately for unexpected movement, E pulses, nonzero heater output after rejection/fault, implausible readings or a missing safety response.

1. **Read-only / cold start**: `M115`, `M105` (space reports by >1 s), `M114`, `M119`, `M3200 P9`. Check correct device, plausible temperatures/endstops, no active job, targets and reported duty zero, debug level 6 on ordinary boot, no thermal fault on panel. On dual hotend inspect T0/T1 and their output reports.
2. **Normal bounded motion only**, with no heater or E command: establish homing safely using the machine-specific reviewed homing procedure, then ensure X is away from both limits and nozzle/bed clearance is safe. `G21`, `G91`, `G1 X1 F60`, `M400`, `M114`, `G1 X-1 F60`, `M400`, `G90`, `M114`. Observe 1 mm out and back, unchanged Y/Z and no heater or E activity. Do not run if homing or clearance is uncertain.
3. **Legacy rejection (isolated heater power/test loads)**: start idle; `M111 S8`, wait for explicit error and cancellation/stop cleanup. `M111 S15`, then `M111 S0`; bit-8 requests report rejection and neither mask can unlock. Individually try `M104 S50`, `M140 S40`, `M109 S50`, `M190 S40`, `M116`, `M83`, `G1 E0.1 F60`, `G1 X1 F60`. Each work command must be rejected or drained, no heating or movement. `M105` and `M114` still report after cleanup. Watch the panel's stopped status and the actual heater/E outputs; serial ok alone is not success. In a separate instrumented run, use valid low-temperature heat requests before M111 to verify an already active bed and hotend both switch off. Stop host, discard its queue, intentionally restart, repeat read-only checks. Do not use M112 to restart a continuing stream.
4. **Independent thermal latch (isolated heater power/test loads)**: `M111 S0`, `M104 S50 T0`, `M140 S40`, `M105` (confirm positive targets and observe requested duty with suitable sensor temperature). `M3200 P5` is the existing diagnostic injection, not a real sensor detection test. Expect fault report `Thermal fault: heaters and extrusion inhibited until restart!`, stop/cancel, fault status on temperature display, all target/duty requests zero and actual outputs inactive. Check `M105`, then `M111 S7`, `M111 S0`, `M104 S50`, `M140 S40`, `M109 S50`, `M190 S40`, `M116`, `M105`. Confirm no renewed duty and no indefinite wait. With safe homing/clearance and disengaged filament feed, `M83`, `G1 E0.1 F60`, `M400` must emit no E pulses. Verify the diagnostic status survives debug changes. Record output shutoff latency at PWM frame boundaries and E pulses with instrumentation; a host replay is not physical certification. Stop host and intentionally restart only after safe output verification.
5. **Normal heating/extrusion separately**, after reset and safe reconnection with power off: verify sensors and heater control first under supervision, with material-appropriate safe temperature and owner-approved limits. Only then perform a tiny E-only positive control with safe nozzle clearance, proper temperature and controlled filament feed; turn off heating and verify both target/duty zero. Never use a cold loaded nozzle to test normal E motion. Actual thermal fault detection and relay/pulse latency remain Task0016 device checks.
