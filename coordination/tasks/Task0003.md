### Flash and SRAM baseline

The tested `Repetier` and `tests` trees are byte-identical to the synchronized integration target and the audit baseline `3a27bd83dfc4711fa2694d18b311b67426f91936`. These measurements apply to that firmware tree.

| Variant | `.text` (B) | `.data` (B) | `.bss` (B) | Flash (B) | Global SRAM (B) | SRAM before runtime use (B) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| RF1000 | 178,138 | 968 | 5,516 | 179,106 | 6,484 | 1,708 |
| RF2000 | 183,058 | 1,282 | 5,356 | 184,340 | 6,638 | 1,554 |
| RF2000v2 | 183,058 | 1,284 | 5,474 | 184,342 | 6,758 | 1,434 |
| RF2000-X44 | 178,112 | 1,120 | 5,500 | 179,232 | 6,620 | 1,572 |

Flash is `.text + .data` out of 253,952 B available for the sketch. Global SRAM is `.data + .bss + .noinit` out of 8,192 B. Here `.noinit` contributes zero bytes in each variant. The CLI and `avr-size` totals agree. The stack and other runtime allocations draw from the remaining SRAM.

### Linked dependencies and symbols

All four linker maps select the same `core.a` members. `main.cpp.o` supplies startup, `wiring.c.o` supplies timekeeping, `wiring_digital.c.o` supplies pin I/O, `WMath.cpp.o` supplies `random(long, long)` for Z-offset scanning, `new.cpp.o` supplies deallocation and `hooks.c.o` supplies the weak `yield` hook. The AVR link also extracts members from `libatmega2560.a`, `libc.a`, `libgcc.a` and `libm.a`. The ELF symbol tables reflect code after link-time optimization.

Arduino CLI resolved zero Arduino sketch libraries for each variant. The ELF symbol tables have zero `TwoWire`, `SPIClass`, `HardwareSerial`, `Stream` or `Print` symbols. The firmware implements TWI in `TwiTransfer` and USART0 in `UsbSerial`. The Arduino `Stream.h` and `Print.h` includes in HAL remain source dependencies.

`PrintLine::queue` occupies 2,861 B and the decoded command queue occupies 175 B in each variant. The linked bed matrix uses 1,300 B on RF1000, 1,100 B on RF2000, 1,218 B on RF2000v2 and 1,250 B on RF2000-X44.

### Timing reference

The linked Timer0 COMPA routine (`__vector_21`) has a 32-cycle STEP-high instruction path on every enabled extruder output. That is 2.0 µs at 16 MHz. E0 uses PORTA bit 4 in all four builds. E1 uses PORTC bit 1 in the two stock RF2000 builds. From the instruction after `sbi` through `cbi`, the disassembly shows four store cycles, one `ldi` cycle, eight `dec` cycles, 15 branch cycles, two `nop` cycles and two `cbi` cycles. [AVR Instruction Set Manual](https://onlinedocs.microchip.com/oxy/GUID-0B644D8F-67E7-49E6-82C9-1B2B9ABE6A0D-en-US-23/index.html)

| Variant | Timer1 COMPA code (B) | Timer0 COMPA code (B) | Timer0 COMPB code (B) | USART0 RX / UDRE code (B) |
| --- | ---: | ---: | ---: | ---: |
| RF1000 | 1,452 | 264 | 842 | 84 / 96 |
| RF2000 | 1,452 | 314 | 1,052 | 84 / 96 |
| RF2000v2 | 1,452 | 314 | 1,052 | 84 / 96 |
| RF2000-X44 | 1,452 | 264 | 1,040 | 84 / 96 |

Physical STEP/DIR timing, interrupt service gaps under sustained print load and the stack high-water mark remain open. [Motion timing plan](../../docs/motion-timing.md)

### Reproduce on a build host

The verified tool versions are Arduino CLI 1.2.2, Arduino AVR Boards 1.8.6, avr-gcc 7.3.0-atmel3.6.1-arduino7, avr-libc 2.0.0 and AVR Binutils 2.26.20160125. The host ran Linux x86-64, Python 3.12.14 and Debian GCC 14.2.0. The Mega 2560 build uses the core's `-Os` and LTO settings at 16 MHz.

```sh
git switch --detach 433fd8d5ed61228ed2c019502bba3c7a2a3e618b
arduino-cli core list
python3 tools/task0003-baseline.py /tmp/rfx-baseline-task0003
```

On a host without the pin, `arduino-cli core update-index` and `arduino-cli core install arduino:avr@1.8.6` fetch the prebuilt packages. Arduino CLI accepts the `ARDUINO_DIRECTORIES_DATA`, `ARDUINO_DIRECTORIES_DOWNLOADS` and `ARDUINO_DIRECTORIES_USER` overrides for a temporary profile. The capture tool accepts `--cli` with an explicit executable path.

Use a clean checkout and a new output directory outside it. The default run exercises the host replays and all four AVR variants. `--host-only` and `--avr-only` run each portion independently. The X44 variant uses RF2000 with `NUM_EXTRUDER=1` and `EXT0_EXTRUDER_COOLER_PIN=X44_PIN`. [Board connector example](../../docs/board-connectors.md)

The capture records the exact commands and source SHA in `commands.txt` and `summary.json`. Each variant produces its ELF, cross-reference map, expanded properties, verbose build log, dependency files, section totals, symbol tables and disassembly. The evidence bundle `RFx000-Task0003-AVR-Baseline.zip` includes these outputs, the replay logs and the six COMPA pulse excerpts in `timing.txt`.
