# Task0035 — Final architecture audit / optional usage accounting

Status: DEFERRED — not ready; no implementation commitment.
Owner direction: 2026-11-28.
Prerequisites: Task0034 P0 completed and Task0032 integrated (including central drive ownership and final resource/real-time qualification). Perform only after the actual final maintained architecture exists. No dedicated branch until activated.

## Owner decision

Remove the complete existing lifetime printing-time and filament-usage counter now. It is not necessary for printer operation. Task0034 owns the removal as part of the current production/EEPROM cutover; see [PR #102 owner handoff](https://github.com/Nibbels/Repetier-Firmware/pull/102#issuecomment-7239220703). No replacement or placeholder counter in P0 or Task0032. Historical research and Git history remain intact.

## Optional final review

Inspect the final firmware's authoritative time, PrintJob, motion/extrusion, persistence and reporting boundaries. Decide whether usage statistics have sufficient practical benefit relative to their complexity, static SRAM, stack, CPU/IRQ cost, EEPROM wear and recovery risk. The default is omission; a documented decision not to implement is a successful completion. Do not invent a counter just to close this task.

If the owner later explicitly elects to add statistics, propose semantics before implementation: distinguish actual powered-on time, active print-job time, heater usage and physically commanded filament motion; account for cancellation, manual filament handling, tool changes, retract/unretract, Advance/ECMP, time rollover, reset and power-loss policy. A commanded motor step is not independent measurement of delivered filament. Reuse existing authoritative central interfaces without duplicated drive/timing or position accounting. No additional hot-path floating point or unqualified per-pulse overhead, no synchronous EEPROM access from the ISR, no wear-heavy settings transactions or safety dependency on optional statistics. Evaluate read-only host/LCD reporting only if wanted. Do not reserve or reuse EEPROM addresses before approved design and validation.

## Acceptance

- Verify legacy counter implementation and all live callers, UI/host reports and storage fields are absent from the integrated firmware; historical records are not production code.
- Record architecture audit outcome and explicit keep-absent versus separately approved implementation decision, with evidence and trade-offs.
- If omission is selected, close without firmware changes.
- If implementation is approved, use normal small-commit, canonical four-board/replay and resource/timing gates; no hardware experiment or flash without separate approval.

This task is not a P0 or Task0032 release blocker, and does not authorize implementation now.
