### AVR timing and stack observations

Read each function using avr-nm address/size and avr-objdump instructions in all four variants. Count static instructions separately from path cycles. For leaf paths enumerate branch and skip alternatives (skip cost depends on next instruction size), count LDS/STS/LD/ST/PUSH/POP/SBI/CBI/ADIW/SBIW as 2, ordinary arithmetic 1, taken/not-taken conditional branches 2/1, RJMP 2, JMP 3, CALL/RCALL 5/4 and RET/RETI 5 on 3-byte-PC ATmega2560. Exclude hardware entry/vector dispatch and interrupt overlap. Structural path costs below are not a WCET for an entire printer workload. All four boards agree for these small leaf-path results.

| Path / metric | Reference | O2 | Relax | No LTO |
|---|---:|---:|---:|---:|
| USART RX ISR cycles, ring full / room | 57/65 | 57/65 | 57/65 | 57/65 |
| USART UDRE ISR structural cycle alternatives | 53/66 | 56/63 | 53/66 | 53/66 |
| Timer0 OVF structural cycle alternatives | 92/97 | 94/95 | 92/97 | 92/97 |
| Timer1 RF1000 long wait, stepperWait high byte nonzero | 124 | 124 | 124 | 92 |
| Timer1 COMPA static instructions RF1000 / v2 | 556/556 | 1443/1445 | 556/556 | 150/150 |
| Timer0 COMPB static instructions RF1000 / v2 | 322/401 | 350/498 | 322/401 | 260/282 |
| performMove static instructions RF1000 / v2 | 1407/1430 | 1803/1843 | 1407/1430 | 770/809 |
| performMove static PUSH count (all boards) | 16 | 20 | 16 | 16 |

Long wait trace: take first BRNE on nonzero high byte; subtract 0x8000 from wait, set return flag, take RJMP after CPSE, restore registers and RETI. Baseline RF1000 from 0x796a, branch 0x79a8 -> 0x79ca -> 0x7c62 -> RETI 0x7c96; no-LTO from 0x13182, branch 0x131b0 -> 0x131d2 -> 0x13286 -> RETI 0x132aa. The 32-cycle saving is 8 fewer saved/restored registers, real but for a long slow wait, not the busy step path. No LTO moves substantial logic into separate performQueueMove/performDirectMove/nextStepSpeed/CPUDivU2/ZMotion::stepPath/finishMove calls; each CALL+RET costs 10 cycles before argument/prologue costs. Do not interpret the smaller ISR symbol as improved sustained step throughput. O2 inlines multiple routines and changes scheduling, e.g. Timer1 and WDT, increases performMove static PUSH count by four and adds stack-allocation RCALLs in its prologue; not an absolute stack high-water result. No measured overall workload gain justifies O2. O2 makes the short USART TX and clock paths trade cycles in opposite directions, not a uniform speedup.

Advance fixed pulse: in all three successful experiments and reference, E0 SBI 0x02,4 and dual E1 SBI 0x08,1, followed by two SRAM stores (4 cycles), LDI (1), DEC/BRNE eight iterations (23), two NOP (2), CBI (2), giving 32 cycles (2 us) from rise to fall. No proven physical low phase or concurrent IRQ margin. This checks the fixed Advance high pulse, not every XY/Z/compensation path.

Relax specific comparison: in all four boards instruction counts and PUSH counts match baseline for WDT, Timer1, Timer0 COMPA/COMPB/OVF, both USART vectors, setTimer, performMove, adjustDirections, updateAdvanceSteps, stepSlowedZCompensation and MotionPlanner::prepareMove. Compared corresponding instruction order, local branch target indices, direct call targets by symbol, and raw operands. Outside CALL -> RCALL shortening, remaining immediate differences occur only in COMPB and performMove (2/4 RF1000, 1/2 dual, 2/4 X44), consistent with relocated Flash lookup addresses; no exhaustive equivalence proof for all linked paths. RF1000 WDT pingWatchdog and Timer1 setTimer each replace CALL with RCALL (1 cycle less per executed call); RF1000 performMove calls to stepSlowedZCompensation, updateAdvanceSteps and isAnyScanRunning also each save 1 cycle when reached. Dual and X44 performMove only isAnyScanRunning call changes in this set. Common UART, Advance fixed pulse, long wait and setTimer body unchanged. Relax therefore shows a real but very small, layout-dependent runtime gain (62.5 ns per shortened call), not a measured general throughput improvement; no SRAM saving. Relaxation also changes trampolines/code addresses and may change other timing paths. It is not a release setting yet.

### Disposition / final verification

Keep pinned -Os with LTO as the common release configuration. This is not a claim every alternative is slower: no-LTO helps the slow Timer1 wait, O2 improves some leaf alternatives and relax shortens specific calls. None has demonstrated a sufficiently broad safe improvement in the high-load motion paths and SRAM/stack envelope to justify a global setting change now. Additional Flash would be acceptable for a proven speed improvement. Retain opt-in experiment switches for reproduction and future targeted work; defer selective optimizer attributes and a separately pinned newer GCC to follow-up if a measured hotspot justifies them (not tested in this matrix, no claim of exhaustive compiler optimum). Prefer source-level SRAM and motion optimization next. No production flags, source or build entry point changed; no runtime physical measurements. A global relax rollout across legacy/Arduino build paths would need further linked and physical timing checks; don't conflate the optional trial with official builds.
