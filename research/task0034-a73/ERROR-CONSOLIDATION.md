## Scan-specific trap found by reading actual callers

ScanSession::requestAbort in CalibrationScan.h preserves first cause, but a DmsUnavailable/DmsOverload can supersede an earlier non-retreat-only cause. Retries are armed/consumed independently. Record final confirmed abort once, not every retry or request. DMS faults prevent automatic homing after retreat; do not replace safety policy with log severity. Both abort methods consume the reason before retreat and other cleanup. Capture evidence before context disappears, but defer EEPROM work until safe top-level service and never block retreat. HBS clears heater targets before existing display; preserve original evidence if needed.

Canceled is NOT exclusively operator cancellation: HeatBedScan.cpp:441–457 reports heater target not admitted / changed then requests Canceled. Distinguish intentional user cancellation from failed thermal admission/change before suppressing logging. Do not lose existing diagnostic information. Preserve first-fault vs later DMS precedence with a replay. Normal matrix save failure at HeatBedScan.cpp:986 and UiActions.cpp:514 can share a typed event with distinct operation context. ZOffsetScan completion screw adjustment (showMyPage, scheduleMessageReturn) is useful normal guidance, not a fault dialog to delete.

PanelMessages.cpp already shares showError/showWarning/showInformation/showMyPage transport via UIDisplay::showMessage; changing only call count is insufficient. ui.cpp:787–794 retains four Flash-text pointers and pushes message menu, used also for normal pages; OK at 829–832 clears UI error flag, not thermal safety latch. Do not remove generic message transport, menu state or acknowledgements needed by non-error workflows merely to save RAM. Find exclusive diagnostic state before deletion.
