## Proposed fix contract
[Marlin M908](https://marlinfw.org/docs/gcode/M908.html) and Repetier 1.x use direct P address/channel and raw S value. [Repetier 2.x](https://docfirmwarev2.repetier.com/GCodes/motion_gcodes/) instead documents RMS mA and optional all-motor addressing. They are NOT semantically interchangeable. Recommendation for RFx000: preserve hardware raw TORQUE code and physical P1..P(3+NUM_EXTRUDER), require S and P for canonical external command; no implicit all-motor write. Do not silently reinterpret S as mA or P as zero-based. Validate original signed int32 before narrowing; reject P0, non-fitted/invalid channels, S below 32 or above per-axis board limit, missing/ambiguous selectors with explicit error and zero register writes. Preserve transient M908 semantics, no EEPROM write or persisted-normal overwrite. Existing nonstandard XYZ/E aliases either fix to correct one-based physical IDs and reject ambiguity or retire after explicit compatibility decision; no silent incorrect axis selection. Prefer canonical P/S-only syntax for simplicity, but do not assume owner has explicitly approved alias removal. No need to add M906/M907 or new persistence syntax for this fix. Convert to nominal amps only for documentation/reporting, not a physical readback. Test all four board profiles, invalid raw signed values (including wrap cases), pause/restore/normal shadow, no unintended register write. Replace baseline counterexample assertions in tests/task0032-drv8711-current.py with desired behavior when production changes land. 250k timing contract remains separate from command semantics.

This note records owner direction and research proposal, not implementation authorization to overlap Task0034. Production fix to be assigned/serialized by current owner; no merge or hardware experiments here.
