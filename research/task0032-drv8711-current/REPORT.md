## 2. Device protocol and board routing

TI [DRV8711 SLVSC40H](https://www.ti.com/lit/ds/symlink/drv8711.pdf), Rev H May 2020, §6.6 p8, §7.5 p27 Figures 17/18. Clock period min 250ns (4MHz), high/low min 25ns each, SDATI setup 5ns/hold 1ns, SCS setup 5ns/hold 1ns, SCS inactive 100ns, SDATO delay max 10ns. 16MHz cycle=62.5ns, rounded minima 4/1/1/1/1/1/1/2 cycles. Active-high SCS, MSB first, write bit 0, address 3 bits, data 12 bits; commit by SCS falling. Device permits inter-bit gaps without time limit while SCS remains high. No maximum SCLK high/low in timing table; interrupted waveform must preserve ordering, minimum widths and stable data/select. No protocol need for full-frame CLI. Reset/wake constraints (10us serial availability, 1ms wake) are distinct from per-bit timing; preserve startup/reset behavior. No documented physical justification for the 1/5us per-bit delays found yet. Task0001 intentionally preserved them; historical electrical/EMI motivation remains unknown. Do not infer optimal real-board clock solely from IC datasheet.

pins.h/fastio.h: SCLK PD5 / 93; SDATI PD6 / 94; SDATO PD4 / 92 on all builds. Hardware SPI uses PB1/PB2/PB3 (52/51/50), not these nets. USART synchronous/MSPIM routes are not a pin-mux solution either; XCK1 is PD5 but TXD1/RXD1 are PD3/PD2, not SDATI/SDATO. No stock hardware-SPI replacement without board wiring modification; not proposed. Software GPIO is appropriate.

SCS X PL0, Y PL2, E0 PL6, E1 PJ7, Z PL4 (RF1000) or PB6 (RF2000 family). On RF1000 Z STEP PL3, DIR PL1; RF2000 family Z DIR PL1. PORTL shares real motion pins. Linked select/deselect emits LDS/ANDI or ORI/STS (extended I/O), not atomic SBI/CBI. Existing select operations outside CLI already allow stale snapshot race: read PORTL with Z STEP low, step IRQ raises STEP, foreground writes stale low while changing SCS; shortened/missing pulse. Reverse race can reassert an old HIGH. DIR and other port writers also matter. DDRL/J RMW can race if other writers exist. PD5/PD6 directly compile SBI/CBI. Direct literal whole-port OUT/STS to PORTD/DDRD not found in four disassemblies by mnemonic scan; indirect writes and all ISR call graph still require proof. No blanket claim that any ISR is safe. Protect each extended-port RMW with save SREG/CLI/LDS/modify/STS/restore SREG; expected 6 cycles from CLI completion through restore, verify linked candidate. If ISR itself uses unsafe nested full-port writes, fix ownership jointly with Task0032 step-output owner. Serialize all DRV bus operations in foreground (including reset, microsteps and future readback); IRQ must never acquire bus or call current setter. Do not use global critical section across a frame. Preserve safety and STEP/DIR priority. For a state machine, do not allow other services to re-enter while SCS asserted, and ensure bounded wall-time completion without starving thermal service.

## 4. Pause/current lifecycle

Drv8711::configuredCurrents is normal configuration shadow, NOT actual register readback. stageCurrent changes saved RAM only; applyConfiguredCurrent programs it. Eeprom.cpp captures configured values, validates board max/min on load; UI stages, writes EEPROM/checksum then applies. M908 and setExtruderCurrent do not stage or persist. PrintPause::serviceStandby waits strictly past 60000ms after settled warm pause (or explicit third Pause sets deadline now; 240000ms extra warm grace after reheat); only fitted extruders written to 32; no XYZ reduction. Phase Standby; target reduced separately. restoreExtruderTemperatures writes latest configured E currents BEFORE heat wait and return motion; second Play after heating resumes print, short warm pause restores too. Existing canonical pause replay stubs current setter as no-op; task-private tests/task0032-drv8711-pause.py instruments a temporary copy with distinct normal/effective shadows and verifies both tool counts, strict boundary, one-shot standby, staged configuration retained/changed while paused, restoration before heat/return. No shared tests modified. Note actual UI applies newly configured current even in standby, so can bypass standby reduction; M908 may override too. No authoritative effective-current shadow currently. Manual E admission includes settled standby (temperature/pressure and jog conditions separate); audit jog, abort, tool change, disabled/reset driver and full reload before new policy. Do not preserve a transient M908 override across pause unless owner explicitly chooses it; current restore reverts to configured value.

Proposed ownership model: normal current (persisted), effective target selected by priority (disabled/fault, standby, temporary explicit override if admitted, normal), last transmitted value/validity (not hardware readback). EEPROM snapshots only normal; no persistence of pause/boost. Configuration changes while in standby should stage normal but not bypass standby cap unless intentional manual service transition. On resume ensure required current applied and electrical readiness before return/queue admission. Do not assume disabling bridge or lost driver state follows shadow; invalidate on reset/power loss. No production change from this branch.

## 5. Electrical/mechanical feasibility of acceleration-dependent current

[RF1000 schematic I851 CTC V2.1](https://asset.conrad.com/media10/add/160267/c1/-/en/001007508CD01/circuit-diagramm-1007508-renkforce-rf1000-3d-printer.pdf), [RF2000 I851 CTC V3.0](https://asset.conrad.com/media10/add/160267/c1/-/en/001395717CD01/schema-electrique-1395717-renkforce-rf2000-imprimante-3d-appareil-pret-a-lemploi-banc-dimpression-chauffant.pdf) (correct full RF2000 URL in docs/board-connectors.md). Both sheet Motor Driver 1+2 show 0.033 ohm sense resistors; RF1000 sheets 4+5 also same. Verify actual v2/replacement PCB and all populated channels before physical approval. CTRL 0x0E01 sets ISGAIN=20; DAC reference nominal 2.75V (range 2.50..3). Datasheet §7.3.4: I_FS = 2.75*TORQUE/(256*20*0.033) = 0.016276 A/code nominal full-scale phase chopping threshold, not PSU current or true measured winding current. 32=0.521 A, 90=1.465 A, 105=1.709 A, 110=1.790 A, 120=1.953 A, 126=2.051 A, 140=2.279 A, 145=2.360 A, 150=2.441 A. VREF/gain/sense tolerance, blanking, decay and back EMF affect actual. CTRL gains, dead-time and microstep mode must not be changed for current control. TORQUE 0x1100|level retains existing SMPLTH selection. TOFF=16us, TDECAY=2us, auto mixed decay; BLANK reset left unchanged. DAC full-scale 10–90% response max 5us; analog threshold update is not winding-current settling. Current loop is in driver, not firmware.

Winding equation L di/dt = V_applied - R i - e(omega). Ideal positive-drive bound I_inf=(V-e)/R, t(I0->I1)=(L/R)*ln((I_inf-I0)/(I_inf-I1)) when I_inf>I1. At hypothetical 24V, 2ohm, 4mH, step 1.5->2 A: e=0 ~98us, e=12V ~236us, e=20V only asymptotic, e=22V cannot reach target. This is illustrative (not measured RF motor parameters); real chopper OFF/blanking, winding angle and changing electrical angle can worsen. Increasing requested current at high speed may produce no extra torque due to back EMF/voltage headroom. Mechanical acceleration load ~ J*alpha plus friction/gravity/process load; acceleration alone misses holding torque, extrusion pressure, axis velocity, corners and resonance. For linear unsaturated region torque roughly proportional to current; saturation and thermal derating reduce benefit. 110->145 codes +31.8% current at most ~+31.8% torque in ideal unsaturated low-speed case, copper I^2R +73.8% while boosted. Motor temperature depends on RMS current over thermal time constant, ambient, cooling and duty. Drivers' external FET/shunt temperature, connectors, wiring, PSU bus sag and simultaneous heaters/motors require budget; driver OCP/OTS is not motor thermal protection. Bus current cannot be obtained by summing phase currents; use energy/power including regenerative decay, mechanical work, converter losses, supply transient limits. Raising all axes concurrently especially risky. TI [TIDA-00740 auto-torque](https://www.ti.com/tool/TIDA-00740) is useful later research, not a stock board capability proof.

Recommendation: first reliable ordinary/standby current writes, then optional low-rate foreground phase-aware feed-forward using known future mutable profile, conservative configured caps, velocity/back-EMF region, hysteresis/dwell, boost token/thermal and PSU budget. No per-step/per-segment SPI in Timer1. Apply before acceleration with enough measured lead time and acknowledge effective target; if deadline missed, retain proven normal current/acceleration envelope, never assume boost. Do not delay STEP to wait for discretionary current. Compare fixed normal current vs lower cruise + normal boost (energy objective) vs higher boost within calibrated cap (performance objective); no automatic increase of configured motion limits. Motors' actual R/L/Kt/Ke/torque-speed/saturation curves, inertia/load, PSU rating and temperature sensors required for quantitative benefit; no hardware experiments authorized. Candidate purely optional, not part of P0 or governor release gate.

## 6. Transport/packing contract and candidate plan

Consume Task0033 handoff 4cdb22106e66c02f86dffeb3f49a6a15506c2038, 250000 baud target (640 cycles/byte), 500000 sensitivity (320), conservative planning 20000 RX bytes/s, normal RX<=80, entry-to-UDR<=40, ready-to-UDR<=512, nonpreemptible guideline<=400 cycles. Current ~1928 cycles already exceeds even entire 250k byte budget 3x. Conservative isolated two-completed-byte FIFO screen with all phases, no shift-register slack, initial occupancy0/1, 40 cycles to first UDR read: both 1904 and 1928 cause possible loss in every phase at both rates (max missing 2/3 at 250k, 5/6 at 500k). This is not exact AVR DOR or proof of historical corruption; actual shift register, next start, priorities, previous occupancy and pacing matter. At 400-cycle mask and one queued byte, 500k screen still 121/320 phases lose; cannot equate single mask budget with guarantee. At 6-cycle isolated mask +40 read budget no loss in this abstract screen; competing IRQs and recurrent windows still need integrated proof. 250k transport budget cannot be used to approve 500k without revisiting.

Candidates to compare: A preserve old bit timings but preempt frame; protect only non-atomic CS/DDR writes. B shift word once per bit rather than recomputing mask; choose explicit conservative SCLK widths, e.g. compact AVR loop with balanced skip/CBI/SBI (5), SCLK SBI (2), two NOP (2), SCLK CBI (2), LSL/ROL (2), DEC (1), BRNE (2, last1) =255 cycles for 16 bits plus setup/select/call. HIGH 4 cycles, setup >=2, period ~16 cycles=1MHz, subject to physical validation. This is modeled candidate assembly, NOT linked candidate result. C unroll to eliminate loop/shift if real CPU improvement worth Flash; D cooperative foreground split only if needed for wall-time fairness, no new ISR. Start with A to isolate protocol vs optimization; hardware-safe behavior not asserted before qualification. Single bus owner, ensure CS inactive min and only selected driver sees exactly 16 valid rising edges. Preserve broadcast init and reset, readback optional future; no changes to microsteps or existing EEPROM integration here. Cost of candidate ~16us raw frame instead of 120us exclusive, plus wrapper; blackout target only <=6 cycles per extended-port write, not frame. Validate exact linked candidate opcodes, worst ISR preemptions at every instruction/edge, actual full-port writers, extended GPIO race, STEP/DIR min widths, RX service windows, thermal/PWM/Advance, stack, abort/reset, pause/manual E, reentrancy. No change to packing based on average CPU alone.

Foreground governor demand add f_writes*C_full/F_CPU, separate blackout max and recurrence. Example at 200 updates/s on each XY axis (400 frames/s): current 1928 cycles/frame excluding wrapper ~4.82% CPU; optimized illustrative 255 cycles/frame ~0.64% plus wrapper. At 1000 segments/s*2 axes*2 changes (4000 writes/s), current ~48.2% vs model ~6.38% plus wrapper and evaluation; unacceptable justification for per-segment control. Limit/coalesce writes, no arbitrary fixed rate selected. Pause 1/2 extruder transitions infrequent but burst can still lose RX or defer STEP/PWM. Use measured C_full/blackout with print-core model rather than additional independent queue model.
