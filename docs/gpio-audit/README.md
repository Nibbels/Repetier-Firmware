# ATmega2560 GPIO access audit · 2026-11-27

**A foreground LCD write can undo the Timer1 Z-enable edge on all four boards.** The Task0034 change protecting PH6 during RGB updates works at the inspected revision. Correcting the LCD and DRV chip-select writers does not require changing every fastio write or adding a port shadow. No production patch, hardware test, or release qualification is part of this evidence branch.

* **Preemption:** Timer1 COMPA masks its own source, then reopens global interrupts at points in StepExecutor.cpp:210/379/389/433/453/497 and ZMotion.cpp:137. Timer0 COMPA (Advance), COMPB (heater/fan/ADC/key sampling), overflow, UART and, per profile, watchdog or Timer3 lease expiry can interrupt an open Timer1 interval. Timer1 masking does not protect foreground port updates. ISR entry alone only protects code up to a subsequent interrupt enable. PWM's fastAction samples buttons; it does not redraw LCD. Stock E edges use low-I/O bit writes; protected runtime core E-enable writes preserve neighboring E/fan pins. No additional nested-ISR clobber of H/K/L was established on these profiles. The noncanonical pin-62 example would add precisely such an ISR writer.
* **DDR, PIN and peripheral handoff:** SET_OUTPUT/SET_INPUT also compile to RMW on extended ports. PORT and DDR are different latches, so LCD DDRK does not itself race with PORTK Z-enable. Boot GPIO setup precedes HAL::setupTimer; Arduino interrupts may already be enabled. Runtime LCD re-init changes direction; DRV select also configures DDR in foreground. No normally running motion/PWM ISR changing those DDR bits was identified. Key/endstop PIN reads have no writeback; no firmware PINx assignment was found in the audited expansions. Do not use PINx read/OR/write as a shortcut: ones written to PINx toggle output latches. For heater initialization consider writing inactive PORT before enabling DDR, as Lighting does; reset defaults alone do not demonstrate glitch-free handoff from an arbitrary bootloader.
* **Indirect path:** HAL.h:355–366 delegates runtime pins to core 1.8.6 wiring_digital.c:29–60/138–163. The core saves SREG and disables interrupts around indirect DDR/PORT updates, then restores SREG. Its timer-disconnect step precedes the digitalWrite port guard; the supported E-enable pins D24/D30 have no PWM channel. TWI pinMode sets both DDR and pullup under core protection. A volatile pointer or a mask by itself supplies no exclusion. UART, TWI, timer COM and ADC peripheral registers are not GPIO latch writes.
* **Cost:** clocks counted from CLI through SREG restore inclusive. b/lease RF2000/v2/X44 RGB set 8 clocks (0.500 µs), init 12 (0.750 µs). q set 8, init 16 (1.000 µs) because LTO materializes two indirect addresses inside the guard. One preceding IN costs one additional CPU cycle outside blackout. A constant high-port single-bit LDS–ORI/ANDI–STS with CLI/restore costs 7 clocks inclusive when contiguous; validate actual conditional branches after patch. Low-port SBI/CBI needs no software exclusion. The 250 kbaud 8N1 byte interval is 40 µs; individual window costs do not prove a worst-case IRQ response under load.

## Reproduction and integration

Build at the exact revisions with the four board definitions in tools/task0003-baseline.py. For example:

```sh
arduino-cli compile --fqbn arduino:avr:mega:cpu=atmega2560 \
  --build-property compiler.cpp.extra_flags=-DMOTHERBOARD=DEVICE_TYPE_RF2000 \
  --build-path /tmp/gpio-rf2000 Repetier
avr-objdump -d -C -z /tmp/gpio-rf2000/Repetier.ino.elf > /tmp/gpio.asm
python3 gpio-inventory.py /tmp/gpio-rf2000/compile_commands.json
python3 gpio-witness.py /tmp/gpio.asm
python3 gpio-rgb-window.py /tmp/gpio.asm
```

Run the scripts from this audit directory with paths to the appropriate checkout/build. The RGB check applies to b/lease/q RGB boards. The LCD witness matches the linked three-instruction E-high and Z-enable sequences, explores each instruction boundary with all 128 initial latch values having PK0 clear, and finds 256 failing schedules out of 512. These are deterministic schedules, not a field failure rate. Use full objdump for indirect addressing or any unrecognized compiler sequence. For q, apply the single qualifier in a throwaway checkout and use tests/heater-lease-integrated-avr.py with its recovery layout retries. For a second ownership counterexample use `-DFAN_BOARD_PIN=9`. For the first ownership negative experiment add `-DEXT0_EXTRUDER_COOLER_PIN=62` to the RF2000 board flags.

**Integration order.** Task0034 owns the enum qualification, heater and lighting. Carry the LCD shared-port correction on its own small branch with motion and UI replay; preserve the 16×4/20×4 geometry and strobe timing. Reconcile PL chip-select guards with DRV transport PR #107 before integration. Add compile-time profile checks separately. For the corrected code invert the lost-update acceptance criterion, inject a pending interrupt before, between and after each protected operation, start with both I states, and check actual disassembly and nested service latency in all four canonical AVR builds. Do not mask delays or an entire display frame. This report establishes software witnesses; hardware waveform, absolute worst-case system latency and physical thermal qualification are separate evidence.
